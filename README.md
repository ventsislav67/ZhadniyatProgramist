# 🍺 Кръчма „Жадният Програмист“

Десктоп система за бай Пешо — собственик на кръчмата срещу софтуерната академия. С нея той следи кой програмист какво е поръчал „на тефтер“, колко дължи и кога за последно е казал „При мен работи!“.

Проектът е завършено C# WinForms приложение с реална база данни, модерен тъмен интерфейс, анимации и пълна защита срещу SQL Injection — подходящ за училищен проект или интервю за работа.

## Технологии

- **C# / .NET 8** (WinForms)
- **SQLite** чрез NuGet пакета `Microsoft.Data.Sqlite`
- **ADO.NET** — директни SQL заявки без ORM (без Entity Framework)
- **Parameterized SQL Queries** — навсякъде, където влизат данни отвън
- **Custom UI контроли** — собствени ModernButton, ModernPanel и AnimatedComboBox
- Целият интерфейс е на **български език**

### Защо SQLite, а не SQL Server LocalDB?

Заданието позволяваше избор на по-практичния вариант. SQLite беше избран, защото не изисква никаква инсталация или конфигурация — базата е един файл (`krachma.db`) до .exe файла и проектът тръгва с едно F5 на всяка машина. ADO.NET кодът (връзки, команди, параметри, reader-и) е идентичен по стил с този за SQL Server, така че демонстрира същите умения.

## Как се стартира

1. Инсталирай **Visual Studio 2022** с работния товар „.NET desktop development“ (или самостоятелно .NET 8 SDK).
2. Отвори `ZhadniyatProgramist.sln`.
3. При първото отваряне Visual Studio автоматично ще възстанови NuGet пакета `Microsoft.Data.Sqlite` (нужен е интернет само този първи път).
4. Натисни **F5**.

Алтернативно от командния ред (Windows):

```
cd ZhadniyatProgramist
dotnet run --project ZhadniyatProgramist
```

## Как се създава базата

**Автоматично.** При първото стартиране `DatabaseHelper.InitializeDatabase()` създава файла `krachma.db` до .exe файла, двете таблици и примерните данни (5 програмисти, 14 поръчки). При следващи стартирания данните се запазват.

Скриптът `SQL/create_database.sql` съдържа същата схема и данни за документация или ръчно изпълнение:

```
sqlite3 krachma.db < create_database.sql
```

За да нулираш базата до примерните данни, просто изтрий `krachma.db` от папката `bin\Debug\net8.0-windows\` и стартирай отново.

### Схема

- **Programmers**: `Id` (PK, autoincrement), `Name`, `FavoriteLanguage`
- **Tabs**: `Id` (PK, autoincrement), `ProgrammerId` (FK → Programmers.Id, ON DELETE CASCADE), `ItemName`, `Price`, `Date`

## Функционалности

- **Loading екран** — заглавие, анимиран progress bar с градиент, процент и хумористични статуси на бай Пешо, които се сменят; плавен fade-out към главния прозорец.
- **Таблица с всички поръчки** — DataGridView с данни от SQL JOIN (имена вместо ID-та), тъмна тема, цветен header, алтернативни редове, цени във формат „12.50 лв.“, автоматично оразмеряване.
- **Избор на програмист** — стилизиран анимиран ComboBox; при избор дългът се изчислява с SQL SUM и се показва в голям панел, чиято сума „тича“ плавно до новата стойност.
- **Цветна скала на дълга** — 0 лв. → зелено „Чист е! Засега…“; под 20 лв. → кехлибарено; над 20 лв. → червено предупреждение; над 50 лв. → яркочервено „Бай Пешо вече гледа лошо!“.
- **Плати сметката** — потвърждение, parameterized DELETE, обновяване на таблицата и сумата, съобщение „Сметката е платена. Бай Пешо временно е спокоен.“ Обработени са и случаите без избран програмист и без дълг.
- **Добавяне на поръчка** — с валидация: избран програмист, непразно име, положителна цена (приема и запетая, и точка).
- **Добавяне на програмист** — с валидация за непразно име и език; и двете падащи менюта се обновяват веднага.
- **Търсене** — живо филтриране на таблицата по име на програмист, поръчка или любим език (LIKE с параметър).
- **Статистика** — четири информационни карти: общ брой програмисти, активни сметки, обща сума на дълговете и най-затъналият програмист.
- **Бай Пешо** — анимиран персонаж в десния панел, който сменя емоция, реплика, цвят и анимация според дълга (виж секцията по-долу).
- **Анимации** — fade-in на главния прозорец, анимиран hover на бутоните, „пулсираща“ рамка на падащите менюта, плавна смяна на сумата и цветовете в панела с дълга, анимиран loading bar. Всички са с леки WinForms Timer-и и не пречат на работата.
- **Responsive поведение** — целият интерфейс е върху TableLayoutPanel-и с процентни колони и Dock, така че нищо не се застъпва и не излиза извън екрана при преоразмеряване (минимален размер 1200×800).
- **Error handling** — всяка операция с базата минава през общ метод `Safe(...)`, който хваща грешките и ги показва като съобщение, вместо приложението да крашва. Няма краш при празна база, невалидна цена или липсващ избор.

## Бай Пешо — анимиран персонаж

В десния панел, под панела „Общ дълг“, живее самият бай Пешо (`Controls/PeshoCharacterControl.cs`) — интерактивен custom контрол с PictureBox, балонче с реплика, надпис „Бай Пешо следи тефтера“ и цветна рамка. Той реагира на дълга на избрания програмист чрез метода `peshoCharacter.UpdateMood(decimal debt)`:

| Дълг | Емоция (`PeshoMood`) | Реплика | Цвят | Анимация |
|---|---|---|---|---|
| 0.00 лв. | Happy | „Браво! Плащаш си редовно!“ | зелено | леко кимане |
| 0.01 – 20.00 лв. | Worried | „Хм… малко си на тефтер.“ | жълто/кехлибарено | бавно поклащане |
| 20.01 – 50.00 лв. | Angry | „Доста си натрупал…“ | оранжево | скръстени ръце, леко трепване |
| 50.01 – 100.00 лв. | VeryAngry | „Айде стига бе! Плати си!“ | червено | силно трепване, пулсираща рамка |
| над 100.00 лв. | Furious | „Изчезвай! Няма да ти давам повече на тефтер!“ | силно червено | агресивно трепване, бърз пулс |

Допълнителни реакции:

- **„Плати сметката“** → `peshoCharacter.Celebrate()`: Пешо става щастлив, казва „Ей така те искам!“ и подскача за кратко (celebratory анимация).
- **Нова поръчка** → `peshoCharacter.ReactToNewOrder(newDebt)`: настроението следва новата сума на този, който е поръчал, а над 50 лв. репликата става още по-строга: „Пак ли поръчваш?! Първо си плати!“.
- **Без избран програмист** → `peshoCharacter.ShowIdle()`: Пешо спокойно „диша“ и чака.

Анимациите (кимане, поклащане, трепване, подскачане, пулс на рамката) са синусоидни отмествания на картинката и плавни цветови преходи, задвижвани от един Timer на 30 ms — леки са и не пречат на работата.

### Изображения и fallback

Петте емоции са PNG файлове в `Assets/Pesho/` (cartoon кръчмар с каскет, гъсти вежди, голям мустак и престилка, съобразен с тъмната тема). ## Как е защитен от SQL Injection

Всички заявки, които приемат стойности отвън (текст от потребителя или избрано Id), използват **параметри** — никога конкатенация или интерполация на низове. Пример от `DatabaseHelper.PayTab`:

```csharp
command.CommandText = "DELETE FROM Tabs WHERE ProgrammerId = @ProgrammerId;";
command.Parameters.AddWithValue("@ProgrammerId", programmerId);
```

Дори търсенето минава през параметър:

```csharp
// WHERE клаузата е фиксиран текст; потребителският вход влиза само тук:
command.Parameters.AddWithValue("@search", "%" + searchText.Trim() + "%");
```

Така въведеното от потребителя винаги се третира като *стойност*, а не като част от SQL кода — злонамерен вход като `'; DROP TABLE Tabs; --` просто се търси буквално като текст.

## Как работи JOIN заявката

Таблицата на главния екран не показва голи ID-та. `DatabaseHelper.GetOrders` свързва двете таблици по външния ключ:

```sql
SELECT p.Name             AS "Програмист",
       p.FavoriteLanguage AS "Любим език",
       t.ItemName         AS "Поръчка",
       t.Price            AS "Цена",
       strftime('%d.%m.%Y %H:%M', t.Date) AS "Дата"
FROM Tabs t
INNER JOIN Programmers p ON p.Id = t.ProgrammerId
ORDER BY t.Date DESC;
```

За всяка поръчка (`Tabs`) INNER JOIN намира съответния ред в `Programmers` по условието `p.Id = t.ProgrammerId` и „залепя“ името и любимия език към реда. Колоните са с български псевдоними, така че DataGridView ги показва директно с правилни заглавия.

## Как работи сумирането на дълговете

При избор на програмист от менюто се изпълнява агрегираща заявка:

```sql
SELECT COALESCE(SUM(Price), 0) FROM Tabs WHERE ProgrammerId = @ProgrammerId;
```

`SUM(Price)` събира цените на всички поръчки на този програмист. `COALESCE(..., 0)` гарантира, че при нула поръчки резултатът е `0`, а не `NULL` — така приложението не крашва при „чист“ клиент. Резултатът се подава на анимацията, която плавно променя показаната сума и цвета на панела според скалата на дълга.

## Как работи плащането на сметката

1. Проверява се дали има избран програмист — ако не: „Първо избери програмист.“
2. Дългът се взима наново от базата — ако е 0: „Този човек вече е чист. Не го тормози.“
3. Показва се MessageBox за потвърждение с името и точната сума.
4. При „Да“ се изпълнява parameterized DELETE (виж примера по-горе), който изтрива всички записи на програмиста в `Tabs`.
5. Обновяват се таблицата, статистиката и панелът с дълга (сумата се анимира надолу към 0 и става зелена).
6. Показва се „Сметката е платена. Бай Пешо временно е спокоен.“
